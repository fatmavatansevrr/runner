## 4. `DOMAIN_DECISION_REQUIRED` — 2D LongHorizon GE-segment weekly structure

### 4.1 Why this is genuinely different, not a mechanical extension

Every prior GE precedent (4D, then 5D per `FREQ.6D.12`) shares one structural property 2D's Core/Runway do **not** have: **4D and 5D's own Core/Runway weekly role structure is constant** — the same fixed role list (e.g. 5D's `2×KEY + 2×EASY + 1×LONG`) applies to every week, with no A/B alternation. Because of this, `FREQ.6D.12 §7-9` could describe 5D's GE structure (`1×KEY + 3×EASY + 1×LONG`, constant every week) as *simultaneously* "a direct generalization of 4D GE's own already-approved structure" **and** "structurally consistent with Runway/Core's own constant per-week shape" — these two framings never diverged for 4D/5D, because Runway/Core themselves never alternate.

**2D's Core/Runway do alternate** (`GEN.11 §1`, Model B, frozen): Pattern A (`KEY_SESSION + LONG_RUN`) and Pattern B (`EASY_SUPPORT + LONG_RUN`) alternate continuously, with Pattern B carrying **zero** `KEY_SESSION` slots. This means, for the first time anywhere in this engagement's LongHorizon work, "GE structurally mirrors the existing GE precedent's own literal shape (constant-KEY-every-week)" and "GE structurally mirrors this frequency's own Runway/Core shape" are **two different, mutually exclusive options** — a tension that simply never arose for 4D or 5D, so no prior phase ever had to resolve it, and no existing report answers it either directly or by trivial extension.

### 4.2 The two real candidates

**Option A — GE inherits the Model B A/B alternating structure, unmodified, continuing the same global week ordinal from GE Week 1 (the very first week of the whole plan) through Runway and Core.** Under this option, GE has no separate structural authority at all — it is exactly Runway/Core's existing structure, continued backward one more segment. Roughly half of GE's weeks (Pattern B) would carry zero `KEY_SESSION` sessions, exactly as roughly half of Runway's and Core's weeks already do.

*Argument for*: this is the direct, symmetric extension of `GEN.26 §2`'s own already-approved reasoning for Question 2 (Runway structural continuation) — that reasoning explicitly rejected extending the 5D/6D "reduce quality density by removing one KEY lane" mechanism to 2D on the grounds that "2D's Core already has at most one `KEY_SESSION` per week... there is no second KEY lane to remove," and instead held Runway's structure identical to Core's, treating Runway as "a fixed-length lead-in to the same Core numeric authority, not a separately-calibrated numeric system." GE is, in exactly the same sense, a lead-in to Runway/Core — under Option A, GE simply never becomes a "separately-calibrated numeric or structural system" either, closing the same gap `GEN.26 §2` closed for Runway, one segment further back, for the identical underlying reason (2D has no spare KEY lane to construct a separate GE-specific quality cadence from). No new session-role-count decision, no new catalog structural authority — GE would need only its own numeric growth/target-cap/long-run-share values (§3.9, already resolved), never a new weekly shape.

**Option B — GE uses a fixed, non-alternating, constant-KEY-every-week structure (`1×KEY + 1×LONG`, i.e. every GE week looks like a Pattern-A week), mechanically copying the literal shape of the 4D/5D GE precedent (`FREQ.6D.12`'s "1 moderate KEY session every week for up to 32 weeks" finding).**

*Argument for*: this is the most literal reading of "GE generalizes the existing GE precedent," and `FREQ.6D.12 §9`'s own reasoning for why constant-weekly-KEY is safe (moderate, not maximal, intensity content; a real, evidenced coaching pattern for extended base-building) would still hold verbatim for 2D's own moderate GE content.

*Argument against*: this would mean 2D's GE segment has **more** weekly KEY exposure than Runway or Core ever do (every week, vs. every other week) — the *opposite* direction of every other frequency's GE→Core relationship, where GE's constant-1-KEY/week already matches or is a plateau-equivalent of Core's own KEY cadence, never exceeds it (4D Core is also constant-1-KEY/week; 5D Core is constant-2-KEY/week, GE's constant-1-KEY/week is a *reduction* from Core, not an increase). Under Option B, a 2D athlete would face a **downgrade** in quality-session frequency at the GE→Runway boundary (KEY every week, dropping to KEY every other week) — precisely the kind of discontinuity this engagement has repeatedly treated as requiring explicit, careful product judgment (e.g. `GEN.11 §5`'s taper structural override exists specifically so the plan's final week never lands on a KEY-less Pattern-B shape; `GEN.28`/`GEN.29`'s entire AerobicStrength Pattern-A/B decision process was built around not silently altering stimulus/continuity without an explicit, disclosed product decision). No existing report anywhere in this engagement evaluates or approves a design where quality-session frequency *decreases* when a 2D athlete progresses from an earlier segment into a later one.

### 4.3 Why this phase does not choose between them

Both options are internally coherent, both trace to real existing authority (Option A to `GEN.26 §2`'s reasoning; Option B to `FREQ.6D.12`'s literal GE precedent), and they produce materially different athlete experiences (alternating quality exposure throughout vs. front-loaded weekly quality that steps down at Runway entry) with no existing evidence source, product decision, or coaching-evidence citation anywhere in this repository (`GEN.11`, `GEN.26`, `GEN.28`, `FREQ.6D.12`, or the original 2D handoff document) that directly evaluates a step-**down** in quality-session cadence across a segment boundary — every prior instance this engagement has examined evaluates a step **up** (Runway ramping toward Core) or a same-direction reduction with an explicit, disclosed stimulus-reduction decision (`GEN.29`'s AerobicStrength Pattern-B). This is a genuine coaching/product judgment call, not a mechanically-resolvable engineering question — matching the exact `DOMAIN_DECISION_REQUIRED` bar `GEN.13`/`GEN.21`/`GEN.28` have each used previously in this engagement, and the phase's own explicit instruction to "STOP → classify `DOMAIN_DECISION_REQUIRED`... if genuinely different and not resolvable by extension, do not force-fit the... precedent if it doesn't actually transfer."

**This phase's own assessment, disclosed but not binding**: Option A is the more defensible default if the user wants a decision recommended rather than merely presented, because it requires zero new structural authority of any kind (it is a direct, symmetric application of `GEN.26 §2`'s own already-approved reasoning, not a new invention) and it avoids introducing the only discontinuity direction (a quality-frequency step-down) this engagement has never previously approved anywhere. It is recorded here as a recommendation, not a decision — this phase does not have standing to freeze new 2D LongHorizon structural authority unilaterally, per this engagement's own STOP discipline.
